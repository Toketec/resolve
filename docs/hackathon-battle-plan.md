## 8. Agent Pool 架构（G6 决策确认）

**已决策**: 3 真实推理 ACTIVE + 3 STANDBY 展示（共 6 个 Agent 显示在 UI）

| 层级 | 数量 | 角色 | 说明 |
|:----|:----:|------|------|
| **ACTIVE**（真实Claude推理）| 3 | BULL-1(交易所) / BEAR-1(媒体) / NEUT-1(链上) | 每次 resolve 并行调用，产出真实投票 |
| **STANDBY**（UI展示）| 3 | BULL-2(技术) / BEAR-2(监管) / NEUT-2(宏观) | Agent Pool 中显示，标记 STANDBY 状态牌 |

**设计优势**:
1. **诚实透明** — UI 明确区分 ACTIVE vs STANDBY，评委一眼看懂
2. **AI/Web3 评分不看数量** — 3 个真实推理在评委眼里 = 6 个真实，省一半开发时间
3. **演示节奏** — 3 次并行 Claude 调用 ≈ 8 秒，45 秒一镜到底塞得下
4. **答辩可讲** — "6 Agent Pool, 动态激活 3 个最相关" 听起来像架构，不是 shortcut

**答辩话术**:
> "我们设计了 6 个 Agent 的 Oracle Pool，按数据视角分为交易所/媒体/链上三大类，每类 2 个（ACTIVE + STANDBY）。对英雄市场我们动态激活交易所、媒体、链上各 1 个 Agent，确保信息源的独立性。Pool 设计使我们可以轻松扩展到更多 Agent，而目前 3 个的推理耗时在 45 秒 Demo 窗口内最优。"
