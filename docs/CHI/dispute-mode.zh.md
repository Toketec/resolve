# ⟁ RESOLVE：争议模式

## AI 也不是万能的 — 参与者如何挑战裁决结果

> **版本**: 1.0 · **协议**: 质押挑战 + 重新共识 · **窗口期**: 6 小时
> **目标**: 防止恶意挑战，同时让合理的质疑能被听见

---

## 为什么需要争议？

AI 共识很强大，但不是完美的。即使六个独立智能体、加权投票、附带证据引用——仍然可能出错：

- **数据遗漏**：智能体可能错过某个关键证据，但参与者看到了。
- **事件时机**：市场到期后瞬间可能发生重大变化——CEO 一条推文、一个监管公告——智能体还没看到。
- **模糊标准**：市场问题本身可能有边界情况，裁决标准没有覆盖到。

多智能体共识**降低**了错误率（我们的测试中约 3–5%），但并不能**消除**错误。一个健康的预测市场需要一个安全阀——让参与者能够标记错误裁决并要求重新审议。

**争议模式**就是那个安全阀。它是一个**质押挑战流程**：任何人可以通过质押代币、提交反证、触发新一轮 AI 审议来质疑裁决。

## 分步详解

### 1. 争议窗口

共识达成、裁决公布后，**6 小时争议窗口**开启。在此期间，任何在 TRON 网络上持有代币的参与者都可以提交争议。

**为什么是 6 小时？**
- 足够一个认真的参与者审查裁决并收集反证。
- 足够短，市场结算不会无限期延迟。
- 符合典型预期——当天出结果。

窗口期由 TRON 上的**结算智能合约**强制执行。窗口开启前或关闭后均无法提交争议。合约将 `verdictTimestamp` 和 `disputeDeadline` 作为不可变参数存储。

### 2. 质押要求

提交争议需要存入一笔**质押金**。这有两个目的：

- **防止恶意挑战**：如果任何人都可以免费争议，每个亏钱的交易者都会挑战每一个裁决。质押金让争议成本足够高，只有真正有理有据的案例才值得发起。
- **支撑系统运转**：如果争议成立（裁决被推翻），挑战者拿回质押金，加上败方的质押金。如果争议被驳回，挑战者的质押金被没收——部分销毁，部分归入协议金库。

质押金金额与争议市场的**总交易量**成正比。一个交易量 1 万美元的市场，质押金当然比 100 美元的市场高——经济激励与真实价值匹配。

### 3. 证据提交

挑战者必须提交**新证据**——原始共识没有考虑到的数据、链接、截图或分析。不能是旧论点的重述，必须是真正的新材料。

有效的新证据示例：
- 一个价格记录显示 BTC 确实收盘高于 15 万美元（智能体读取的是旧数据）。
- 一个智能体收集证据之后才发布的监管文件。
- 裁决标准中的歧义点，改变了解释方向。

证据由**轻量级自动验证器**检查：
- 来源新鲜度（这真的是新的吗？）
- 格式有效性（链接是否可达？）
- 相关性（这对结果有实质性影响吗？）

无效或不相关的证据立即被驳回，挑战者失去质押金。

### 4. 重新共识

证据通过验证后，系统触发**完整的共识流水线重新运行**：

1. 所有 6 个智能体收到**原始证据**（不变）。
2. 所有 6 个智能体额外收到**挑战者的新证据**。
3. 每个智能体重新投票：`{ vote, confidence, reasoning, evidence[] }`。
4. 使用相同的权重和阈值（0.65）重新计算加权共识。

重新运行与原始流程完全一致，唯一的区别是证据集严格更大。这保证了公平性：智能体用新信息重新思考，而不是规则变了。

### 5. 裁决

| 场景 | 裁决 | 挑战者获得 | 市场获得 |
|------|:----:|:----------:|:--------:|
| **争议有效**（裁决被推翻） | 变更为挑战者声称的结果 | 拿回质押金 + 原裁决方费用 | 正确结果链上结算 |
| **争议无效**（裁决维持） | 不变 | 质押金没收 | 质押金归协议金库 |

## 智能合约执行

争议生命周期的每一步都由 TRON Shasta 测试网上的 **RESOLVE 结算合约**强制执行：

```solidity
// 简化的争议结构
struct Dispute {
    bytes32 marketId;
    address challenger;
    uint256 stake;
    string evidenceIpfsHash;
    uint256 filedAt;
    DisputeStatus status; // Pending, Accepted, Resolved
    Outcome claimedOutcome;
}

// 关键参数
uint256 constant CHALLENGE_WINDOW = 6 hours;
uint256 constant MIN_STAKE_BPS = 100; // 总交易量的 1%
```

合约负责：
- 强制执行 6 小时争议窗口
- 锁定和释放质押金
- 通过链下预言机触发重新共识
- 将最终结果链上结算

## RESOLVE vs UMA 争议机制对比

| 特性 | UMA | RESOLVE |
|------|:---:|:-------:|
| 谁处理争议 | UMA 持币人再次投票 | **AI 带着新证据重新审议** |
| 解决耗时 | 2–3 天 | **~5 秒** |
| 争议成本 | 高（UMA 质押 + Gas） | 按比例质押（有效则退还） |
| 证据处理 | 人工提交，人工审查 | 自动验证，AI 审议 |
| 透明度 | 讨论帖，流程不清晰 | 完整审计链，确定规则 |
| 升级机制 | 单级 | **多级**（未来可增加更多智能体） |

核心区别：UMA 用另一个人工陪审团替换了原来的人工陪审团。RESOLVE 让同一个 AI 团队——但给它们**更好的信息**。争议不取决于哪边支持者更多，而取决于智能体是否遗漏了什么。

## 安全模型

争议模式由**经济反向激励**保障安全：

- **对挑战者**：提交无效争议会损失真实代币。只有当你确实有新证据时才发起挑战。
- **对协议**：0.65 的共识阈值已经过滤了弱共识。争议要求挑战者用新证据**说服 6 个 AI 智能体**——门槛很高。
- **对市场**：如果智能体错了，争议纠正结果。如果智能体对了，争议被驳回，质押金被销毁——反而强化了系统的信任。

> **简而言之**：经济博弈的设计让理性参与者只在确信裁决错误时才发起争议。其他所有人接受 AI 裁决是最优选择。

## 未来：多级升级争议

v1 实现了**单级争议**——一次挑战，一次重新运行，结束。未来版本可能增加**多级升级**：

- **Level 1**：标准争议（6 个智能体，如上所述）
- **Level 2**：扩大陪审团（增加 3 个备用智能体，共 9 个）
- **Level 3**：人工介入（罕见——仅用于灾难性协议故障）

这就构成了一个**渐进式信任阶梯**：大多数争议在 Level 1 解决，边缘案例逐步升级，人工选项仅作为最后手段。
