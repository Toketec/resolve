### 差异化壁垒

- **不是 Polymarket 分叉**：我们不是复制一个预测市场再套 ChatGPT——我们是**用 AI 多 Agent 共识替代 UMA 人工投票，作为预测市场的去中心化仲裁层**
- **不是套壳 ChatGPT**：多 Agent 独立推理 → 加权共识 → 链上结算，每一票带证据链可溯源
- **不是 demo only**：TRON 测试网上真实交易 + 真实 AI 推理 + 真实结算
- **Agent ≠ 交易顾问**：Agent 不是帮用户分析该买哪边的——Agent 是**替代 UMA 投票者的仲裁预言机**，市场到期后它裁决结果、触发链上赔付。用户自己选边下注

### 完整流程闭环（4 层分工）

```
阶段                    用户做          Agent做                   系统做             合约做
─────────────────────────────────────────────────────────────────────────────────────────────
① 钱包连接(1min)     连TronLink+签名     —                       UI回显地址            —
② 买入预测(30s)      选YES+金额+签名     —                       写Supabase持仓       buyShares()
③ AI裁决(7s)         纯旁观             6 Agent 并行推理(6LLM)    共识计算+写DB+动画     —
                                          → 6 票加权共识
④ 链上结算(10s)      Owner签名settle    —                       调合约接口            settle()
```

**用户操作总计**：3-4 次点击（装钱包、连钱包、买签名、Owner结算签名）
**Agent操作总计**：6 次 LLM 调用 + 1 次 x402 支付（全自动，约 5-6 秒）

**一句话定位**：不是"一个带 AI 功能的预测市场"——而是**用 AI 多 Agent 共识替代人类代币投票者，作为预测市场的去中心化仲裁层**。

## 4. 技术战略

### Hybrid 数据架构

混合使用 Supabase Postgres（持久化）与内存缓存（Demo 现场的即时读取），在零成本基础设施上实现演示所需的实时响应。

- 类型定义集中位于 `packages/shared/src/index.ts`——唯一事实来源
- A 和 B 写入结果，C 读取渲染，通过 5 个 API 接口契约互连
- 桩（stub）阶段全部用内存 Map 实现，后期换入真实 Supabase 客户端

### 6 Agent Pool（全部 ACTIVE，6 维并行裁决）

| 层级 | 数量 | 角色 | 说明 |
|:----|:----:|------|------|
| ⚡ **BULL-1**（交易所预言机） | 1 | 看多分析 | HTX BTC 价格、交易量趋势 → 技术分析偏多 |
| ⚡ **BULL-2**（技术预言机） | 1 | 看多补充 | AI/区块链技术面分析——TEE等级、L2扩容 |
| ⚡ **BEAR-1**（媒体预言机） | 1 | 看空/谨慎 | 新闻情绪、监管动态 → 基本面偏保守 |
| ⚡ **BEAR-2**（监管预言机） | 1 | 看空补充 | 全球监管政策风险——SEC、欧盟 MiCA |
| ⚡ **NEUT-1**（链上预言机） | 1 | 中性判断 | 链上数据、持仓分布 → 数据驱动中性 |
| ⚡ **NEUT-2**（宏观预言机） | 1 | 中性补充 | 宏观经济、利率政策、地缘政治 |

**不再有 STANDBY 层级**。全部 6 个 Agent 在市场到期后并行 LLM 推理，各自输出 `{outcome, confidence, evidence[]}`，6 票加权共识。这就是全方位裁决——交易所、媒体、链上、技术、监管、宏观六个维度一个不落。

**总耗时**：6 次并行 LLM 调用 ≈ 5-6 秒（Promise.all）
**成本**：~$0.30-0.60/次 resolve
**答辩话术**：「6 个 Agent 从 6 个独立维度做出全方位裁决，不是 3 个 Agent 的片面判断」

**真实 Claude 推理 + 6 Agent 并行裁决 + 链上结算**

- 非 mock 的 Claude API 调用，每个 Agent 返回 `{ outcome, confidence, evidence }`
- 加权共识数学：按置信度加权汇总，6 票共识，阈值 0.65
- 结算合约预注资，在共识达成时向赢家钱包支付固定 TRC-20 金额
- 测试网气囊按钮：一键模拟确认兜底

### HTX 3 项集成

1. **HTX API**（价格数据只读）——喂给交易所 Agent 做证据
2. **B.AI 8004**（Agent 身份注册）——在 TRON 上注册 AI Agent 身份
3. **B.AI x402**（微支付）——共识达成时触发微支付

## 6. 风险与失分点预判

| 风险 | 概率 | 影响 | 缓解措施 |
|------|:----:|:----:|---------|
| TRON 测试网不稳定 | ⭐⭐⭐ | ❌ 英雄镜头死 | 气囊：模拟赔付按钮 + 备用视频 |
| Claude API rate limit | ⭐⭐ | ❌ AI 推理失败 | 本地确定性 fallback + mock 证据集 |
| 团队协作脱节 | ⭐⭐ | ❌ 切片对接不上 | Walking Skeleton 第一天就走通，接口三天锁定 |
| 初筛材料缺件 | ⭐ | ⚠️ 扣分 | 7/3 前准备所有提交材料 |
| 社区投票不足 | ⭐ | ⚠️ 决赛分少 20% | 提前社区运营 + 推特预热 |
| 演示排练不足 | ⭐⭐ | ⚠️ 现场卡顿/失误 | 7/3 后团队至少走 5 遍完整英雄镜头 |

### 失分点（务必避免）

1. **产品完成度做过头**——花时间做完整 CRUD 或多余页面，核心路径反而没跑通
2. **AI 推理做成 mock**——评委一眼识破，AI/Web3 融合分直接归零
3. **技术太复杂讲不清**——答辩时评委听不懂 Agent Pool 架构
4. **忽视 $HTX 生态展示**——HTX 的 3 项集成必须在 demo 中有所体现
5. **没有备录视频**——现场演示一旦出问题，没有任何可展示的内容
